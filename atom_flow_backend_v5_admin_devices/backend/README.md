# ATOM Flow API (Base)

باك اند بـ Node.js + Express، فيه:
- تسجيل دخول بـ JWT
- **اتصال حقيقي بالـ MQTT broker** بيستقبل قرايات العدادات لحظياً
- Endpoint لعرض بيانات الأجهزة
- Endpoint لإضافة جهاز جديد بـ id تلقائي
- Endpoint للتحكم في relay/valve (on/off) — لسه محلي فقط، مش متصل بفيرموير حقيقي (تفاصيل تحت)

## التشغيل

```bash
cd backend
npm install
cp .env.example .env
npm run dev
```

السيرفر هيشتغل على: `http://localhost:4000` وهيحاول يتصل بالـ MQTT broker تلقائي.

## إزاي MQTT شغال هنا

الفيرموير (`wifi_telegram_modbus.ino`) بيبعت كل 2 ثانية على:

- **Topic:** `sensors/flow`
  ```json
  { "total": 123.4, "flow": 5.2, "velocity": 0.8, "unid": "<platformUID>" }
  ```
- **Topic:** `status/meters` (عند الاتصال/الانقطاع)
  ```json
  { "status": "connected", "unid": "<platformUID>" }
  ```

الـ `unid` هو نفسه `platformUID` المكتوب في إعدادات كل جهاز (متاح لتعديله من صفحة `/` في السكادا القديمة أو من الفيرموير مباشرة).

الباك اند (`services/mqttService.js`) بيعمل subscribe على نفس الـ topics دي، ولما توصل رسالة:
1. بيدور على جهاز عندنا بنفس الـ `mqttUnid`
2. لو لقاه → يحدّث القرايات (`flow`, `velocity`, `total`) و`online: true`
3. لو معندناش الجهاز ده أصلاً و`MQTT_AUTO_REGISTER=true` (الإعداد الافتراضي) → بيتسجل تلقائي كجهاز جديد اسمه "Device xxxxx" عشان تقدري تشوفيه وتربطيه صح بعدين (تعدّلي الاسم/اللوكيشن من `PATCH /api/equipment/:id`)
4. أي جهاز ميبعتش رسالة لمدة 30 ثانية → بيتحط Offline تلقائي

### علشان تختبري بجهاز حقيقي دلوقتي
1. شغّلي الباك اند
2. شغّلي أي RTU بالفيرموير المرفق ومتأكدة إنه متصل بالنت
3. راقبي الـ Terminal، هتشوفي لوج زي:
   ```
   [MQTT] ✅ Connected to broker
   [MQTT] 🆕 Auto-registered new device: sensor-xxxxx (unid=08941d32-...)
   ```
4. اعملي GET على `/api/equipment` (بعد تسجيل الدخول) وهتلاقي الجهاز باسمه وأرقامه الحقيقية

### ملاحظة عن التحكم (Relay/Valve)
الفيرموير الحالي بيستقبل بس `device/{unid}/ping` ويرد `pong` (health check)، لسه مفيش topic لاستقبال أوامر تشغيل/إيقاف فعلية. يعني زرار On/Off في الأبليكشن دلوقتي بيغيّر الحالة في الباك اند بس، مش بيوصل فعلياً للريلاي. لما نجهز، هنحتاج نضيف في الفيرموير subscribe على topic زي `device/{unid}/set` يستقبل `{"relay":"on"}` مثلاً وننفذه فعلياً على الهاردوير، وبعدين نربطه هنا في `handleControl`.

## الـ Endpoints

| Method | Endpoint                    | الوصف                                    | توكن؟ |
|--------|------------------------------|-------------------------------------------|-------|
| GET    | /api/health                 | التأكد إن السيرفر شغال                    | لا    |
| POST   | /api/auth/login             | تسجيل الدخول                              | لا    |
| GET    | /api/auth/me                | بيانات المستخدم الحالي                    | نعم   |
| GET    | /api/equipment               | عرض كل الأجهزة                            | نعم   |
| GET    | /api/equipment/:id           | عرض جهاز واحد (بيانات + لوكيشن + id)      | نعم   |
| POST   | /api/equipment               | إضافة جهاز جديد بـ id تلقائي              | نعم   |
| PATCH  | /api/equipment/:id           | تعديل اسم/لوكيشن/mqttUnid لجهاز           | نعم   |
| PATCH  | /api/equipment/:id/control   | تشغيل/إيقاف relay أو valve                | نعم   |

## الفصل بين المستخدمين (Multi-user)

كل جهاز دلوقتي عنده `ownerId`. اليوزر بيشوف بس أجهزته (+ أي جهاز اتسجل تلقائي من
MQTT ولسه محدش استلمه - ده بيبان لكل اليوزرز لحد ما حد يتفاعل معاه بأي حاجة
زي تسمية/فيفورت/تحكم، وقتها بيبقى ملكه هو بس تلقائي). فيه كمان
`POST /api/equipment/:id/claim` لو عايزة زرار "استلام" صريح في الأبليكشن.

للتجربة، فيه حسابين جاهزين في `data/mockData.js`:
- `admin` / `admin123` → شايف نفس الـ 6 أجهزة المعتادة
- `demo` / `demo123` → هوم فاضي تمامًا (تقدري تضيفيله جهاز وتتأكدي إن admin مش شايفه)

## الحفظ على الديسك (Persistence)

الأرايه بتاعة الأجهزة كانت في الذاكرة بس قبل كده، يعني أي تعديل (زي إعادة تسمية جهاز
اتسجل تلقائي auto-register) كان بيضيع أول ما السيرفر يترستارت. دلوقتي `data/store.js`
بيحفظ نسخة تلقائي في `data/devices.persist.json` بعد أي تعديل هيكلي (اسم/لوكيشن/فيفورت/
تحكم/إضافة جهاز جديد)، وبيرجّعها تاني أول ما السيرفر يشتغل. القرايات اللحظية (flow/velocity)
مش بتتحفظ على الديسك عمدًا (عشان منكتبش على الديسك كل ثانية من غير داعي) - دي هترجع لايف
تاني أول ما الجهاز يبعت بيانات بعد أي ريستارت. ده حل مؤقت لحد ما نستخدم قاعدة بيانات حقيقية.

## الخطوات الجاية

2. إضافة topic تحكم فعلي في الفيرموير (`device/{unid}/set`) وربطه في `handleControl`
3. حفظ تاريخ القرايات (Historical data) لصفحة Reports
4. تشفير الباسورد بـ bcrypt وقاعدة بيانات مستخدمين حقيقية + دعم أكتر من مستخدم (multi-user) مع فصل بيانات كل يوزر عن التاني
5. WebSocket بين الباك اند والأبليكشن للتحديث اللحظي بدل ما الأبليكشن يعمل polling
